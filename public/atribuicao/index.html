Como o crédito é calculado

Um score por contato, depois normalizado

Cada ponto de contato recebe um score bruto. No fim, os scores da matrícula são normalizados para somar exatamente 100% — nada de crédito se perde nem se duplica.

Si = P × T × R posição × tempo × repetição — todos os pesos são configuráveis.
P — posição

Onde o contato aconteceu na jornada

Primeiro e último contato pesam mais (padrão 1,3); intermediários pesam 1,0. Uma única interação recebe peso 1,0.

T — tempo

Quão perto da matrícula

Decaimento exponencial T = 0,5d/h. Contatos mais recentes pesam mais. Meia-vida padrão: 30 dias.

R — repetição

Ganho decrescente ao repetir

R = 1/√n. O segundo clique do mesmo canal/campanha vale menos que o primeiro, o terceiro menos ainda.

Sobre este exemplo

Esta página é a explicação — o app é interativo

O que você vê aqui é um retrato fixo para apresentar ao time. A aplicação de verdade é um app em Streamlit com 7 telas: importação de CSV/XLSX, ajuste de parâmetros, jornada individual, resultados por canal e campanha, comparação de modelos e exportação.

Por que os pesos não são “verdade”. Primeiro/último = 1,3, meia-vida = 30 dias etc. são pontos de partida configuráveis. O objetivo é testar hipóteses de atribuição, auditar cada matrícula e comparar a eficiência relativa dos canais — não cravar um número absoluto.

Para rodar o app completo localmente:

cd attribution_app
pip install -r requirements.txt
streamlit run app.py     # abre em http://localhost:8501

Para virar um site público de verdade, dá para publicar esse mesmo app no Streamlit Community Cloud (ou similar) conectando o repositório.
